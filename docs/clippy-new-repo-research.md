new mascot skin for `pet-clawd`.

The product is: a persistent morphing desktop character that can talk, listen,
see the screen, see the camera on request, inspect apps, ask questions or
approval when needed, and execute computer tasks through an app-owned tool
loop. The visible character is not decoration; it is the status and control
surface for the agent.

- Runtime: native Swift/AppKit macOS app.

- Operator layer: app-owned client tool loop; Claude/Codex can request tools,

## Product Shape

The assistant needs five capabilities in one local app:

1. Visible character: always-on-top transparent mascot window, draggable,
   click-through on transparent pixels, contextual speech/approval bubble,
   morphable tool/status states.
2. Voice: microphone permission, wake or push-to-talk, interim/final
   transcript display, TTS response, barge-in/stop-speaking.
3. Perception: screen capture, UI-tree inspection through Accessibility,
   camera one-shot capture when asked.
4. Action: keyboard/mouse/app/file/shell/browser/computer tools, with fresh
   observation after actions.
5. Control: ask clarifying questions and approval when the requested action is
   ambiguous, destructive, external-facing, financial, privacy-sensitive,
   credential-gated, or has multiple plausible targets.

The body should map directly to runtime state:

- `Listening`: attentive/ear/eye pose.
- `Hearing`: active speech-recognition pose.
- `Thinking`: thought loop.
- `ScreenVision`: magnifier or looking pose.
- `CameraVision`: eye/camera pose.
- `Reading`: document/book pose.
- `Searching`: searching/magnifier pose.
- `Writing`: pencil/paper/typing pose.
- `ComputerControl`: cursor/keyboard/tool pose.
- `WaitingApproval`: question mark or raised eyebrow pose.
- `Done`: checkmark/congratulate/wave pose.
- `Blocked/Error`: alert/confused pose.

## Architecture

### 1. Visual Character Runtime

Use one rectangular borderless transparent `NSWindow` for the character. The
visible shape comes from the renderer's alpha/hit mask, not from the window
shape itself.

Reuse the current Clawd window recipe as local evidence: `CrabCharacter`
creates a borderless `NSWindow`, marks it non-opaque, clear, shadowless, maximum
level, non-ignoring mouse events, and able to join all spaces/fullscreen
auxiliary spaces. `CrabContentView.hitTest` only returns the view when the
renderer says the clicked point is opaque. `CrabCharacter.showBubble` already
anchors a separate bubble window to the mascot.

Renderer choice:

- Start with `CoreAnimationMorphRenderer` using `CAShapeLayer` paths for the
  new morphable mascot. This is the path for "Clippy can become a checkmark,
  arrow, magnifier, question mark, cursor, etc."
- Add `RasterAgentRenderer` for Clippit-compatible packs. This lets the repo
  play 43 classic animations from extracted data without making the whole app a
  sprite-player.
- Avoid SpriteKit/Metal for v1 morphing. SpriteKit is useful for raster packs,
  but the main trick is a shaped transparent overlay plus interpolated vector
  paths.

### 2. Character Pack Contract

`CharacterPack` must describe both geometry and behavior:

```swift
struct CharacterPack {
    var id: String
    var displayName: String
    var defaultSize: CGSize
    var palette: CharacterPalette
    var hitPath: CGPath
    var bubbleAnchor: CGPoint
    var dragAnchor: CGPoint
    var states: [MascotState: [MascotActionName]]
    var morphTargets: [MorphTargetName: ShapeRig]
    var rasterAgent: RasterAgentPack?
}
```

`MascotActionQueue` should mirror the old Microsoft Agent request semantics:
FIFO, request IDs, start/complete/fail/interrupted status, `stopCurrent`, and
`stopAll`. Idle should only run when the queue is empty and should be canceled
by real work.

Minimum command API:

- `show`
- `hide`
- `play(animationName)`
- `speak(text, ttsMode)`
- `think(text?)`
- `gestureAt(point)`
- `moveTo(point, duration)`
- `morph(targetName)`
- `setState(state)`
- `stopCurrent`
- `stopAll`

### 3. Voice Runtime

Reuse Iris's shape, not Iris's product:

- Swift app owns UI/settings/process supervision.
- Pipecat sidecar owns low-latency microphone input, VAD, STT, wake gating,
  LLM/tool flow, TTS, playback, and echo suppression.
- Swift starts/stops the sidecar and receives events.
- Speech events drive body states instead of debug chimes.

Do not copy Iris's notification/debug sounds. The user already said no
chime/notification sounds. TTS is intentional assistant output and is allowed.

Voice event mapping:

- `wake.accepted` -> `Listening`
- `transcript.interim` -> update small live transcript bubble
- `transcript.final` -> `Thinking`
- `assistant.audio.started` -> `Speaking`
- `tool.called` / `tool.started` -> specific tool state
- `tool.finished` / desktop completion -> `Done`
- `tool.failed` -> `Blocked/Error`

### 4. Perception

Use three separate tools so the model can choose the right sensor:

- `observe_screen(question?)`: capture current screen pixels, exclude mascot
  window when possible, downsample to bounded JPEG.
- `observe_ui_tree(target?)`: Accessibility tree / focused app / element at
  point; use this before clicking native controls.
- `observe_camera(question?)`: one default-camera frame on explicit user ask.

Current Clawd already has a CoreGraphics screenshot path with screen-recording
permission, own-window exclusion, max-dimension resize, JPEG compression, and
base64 return. Iris already has separate ScreenCapture, Camera, and Microphone
permission wrappers.

### 5. Operator Tool Loop

The current Clawd app is not enough. It launches Claude CLI and parses assistant
text plus `tool_use`/`tool_result` events, but it does not execute app-owned
tools. A real desktop operator needs an app-owned loop:

1. User speaks/types a task.
2. Model responds with a tool request.
3. The macOS app executes the tool.
4. The app returns a `tool_result` with observation/diff.
5. The loop repeats until final answer, approval request, or blocker.

Anthropic's current tool-use docs match this: client tools run in the
application; Claude emits `tool_use`; the app executes and returns
`tool_result`. Anthropic's computer-use docs also state that the application
must explicitly implement screenshot capture, mouse, keyboard, and other
actions.

Recommended v1 tool registry:

```text

mascot.set_state

observe.camera

computer.scroll

browser.open_url
browser.inspect
ask_user
request_approval

```

Execution rule: every computer action returns a fresh observation or compact
diff. This is what prevents blind clicking.

### 6. Approval And Question Policy

The assistant should ask a short question when it lacks one needed answer. It
should request approval before actions that are destructive, external-facing,
financial, credential-sensitive, privacy-sensitive, or that have multiple
plausible UI targets.

This is product control, not a lecture layer. Approval UI should be a bubble
with the proposed action, the concrete target, and buttons like `Approve`,
`Change`, `Cancel`.

## Microsoft Agent Grammar To Preserve

Microsoft Agent's interaction grammar is the correct source of truth for the
classic Clippy feeling:

- Methods: `Activate`, `GestureAt`, `Get`, `Hide`, `Interrupt`, `Listen`,
  `MoveTo`, `Play`, `Show`, `ShowPopupMenu`, `Speak`, `Stop`, `StopAll`,
  `Think`, `Wait`.
- `Show` plays the Showing state; `Hide` plays the Hiding state.
- `Play` queues a named animation.
- `Speak` displays speech and can lip-sync.
- `MoveTo` and `GestureAt` choose direction-specific animations based on the
  character's current position and the target point.
- Requests are asynchronous and queued; use request-start/request-complete
  style events for correctness.
- Idle is progressive: Level 1, then Level 2, then Level 3.
- Listening and Hearing are separate states.
- Gesture and movement directions are character-relative.
- Moving state animations transition into a move pose; the window position then
  changes.
- Branching, exit branching, zero-duration frames, and Return animations matter
  for faithful raster playback.

Canonical v1 animation/state names:

```text
Show, Hide, RestPose, Blink,
Idle1_1, Idle1_2, Idle2_1, Idle2_2, Idle3_1, Idle3_2,
GestureUp, GestureDown, GestureLeft, GestureRight,
MoveUp, MoveDown, MoveLeft, MoveRight,

Acknowledge, Decline, Suggest, Surprised, Wave
```

## Asset Strategy

Fastest hackathon path:

1. Support modern extracted agent packs first:
   `agent.ts`/JSON-like data + `map.png` + sounds from pithings/pi0 or WPF.
2. Support Cosmo `.agent` packages second:
   `.acd` + `*_sprite_map.png` + `sounds/*.mp3`.
3. Add `.ACS` import later through a conversion script or parser.

Source facts:

- Microsoft docs say `.ACS` is the single local structured character file, and
  `.ACF/.ACA` is the split format used for HTTP/on-demand animation downloads.
- Cosmo/Clippy is native Swift/macOS and SpriteKit, but it does not directly
  support `.ACS`; it expects output from MSAgent Decompiler.
- Cosmo's converter removes BMP backgrounds, builds a transparent PNG sprite
  map with ImageMagick, converts WAV to MP3 with ffmpeg, and emits `.acd`.
- pithings/clippy is a modern TypeScript rewrite with a queued action API,
  TTS, streaming speech, `moveTo`, `gestureAt`, pause/resume, and dispose.
- ms-agent-js is the most complete modern web implementation for docs/tests:
  request system, Canvas/WebP/WebM optimization, interactive balloon controls,
  and direct legacy ACF support.
- TripleAgent and Remy Lebeau's spec are the best references for `.ACS`
  parsing and frame-level quirks.

For an open-source public repo, keep the runtime independent of Microsoft-owned
assets. For this side hackathon, Fable can add an import/download path or local
asset pack path so development can use Clippit-compatible assets without making
the code architecture depend on them.
